# play — 하버드 뇌놀이

입력은 사용자가 선택한 동화·철학 에세이와 연령·활동 맥락이다. 필요한 입력이 외부에서 제공됐다면 다른 단계를 실행하지 않는다. 제공되지 않은 에세이를 자동 생성하지 않는다. 일부 입력 없이 진행하라는 명시적 요청이 있으면 그 한계를 표시한다.

'하버드 뇌놀이'는 프로젝트의 콘텐츠 이름이다. 대학 공식 프로그램·인증·보증이나 특정 효과의 입증으로 표현하지 않는다. 연구 원리의 근거와 창작 놀이의 검증 여부를 구분한다.

후보의 `thinking.activities` 중 선택 활동에 작성한다. 관찰·이유 설명·관점 바꾸기·비교·상상·감정 표현·생활 속 적용을 조합할 수 있으며 활동/단계 수는 고정하지 않는다.

- 활동: `id`, 선택적 `title`, `description`, `steps`, `references`, `extensions`.
- 단계: `id`, 선택적 `title`, `goal`, `questions`, `explanation`, `extensions`.
- 아이가 할 활동, 후속 질문, 연령별 변형, 준비물·시간 등은 단계/활동의 extensions에 선택 저장한다. 예: `extensions.childAction`, `followUpQuestions`, `ageVariants`.
- 열린 질문과 충분한 기다림을 제안한다. 특정 답·감정 표현을 강제하지 않는다.
- 확인한 문헌만 references에 사용한다. 미확인 자료는 검토 메모에 남기고 검증 상태를 명시한다.
- 기존 ID와 다른 활동은 보존한다. 출판용 harvardPlay.desc로 직렬화하지 않는다.

연령·정서적 부담·활동의 실제 난이도·원고와의 철학적 연결을 검토한다. 뇌 발달 보장이나 과장된 신경과학 표현은 새로 작성하지 않는다.

## 분류·순서·번호 (Master Draft v1 선택 관례)

Essay는 철학적 문제·원전/개념·문학적 해석·논증·발달/교육적 시사점·결론의 독립적인 글이다. 실제 부모/아이 발화·후속 질문·관찰/실험·만들기·생활 실천은 Play 후보로 분류한다. 제목의 ‘3.’ 같은 번호가 아닌 문단의 **기능과 의미**를 기준으로 판단한다. 교육학적 설명은 무조건 Play가 아니며, 이론적 맥락도 활동 이해에 필요하면 남길 수 있다. 모호한 경우 원문 위치·분류 제안·이유를 보고하고 사용자 검토를 기다린다. 영역 이동은 원문과 후보를 비교하며 삭제·의역 없이 제안한다. 원문 번호가 중요한 참조라면 제거하지 않는다.

권장 흐름은 **부모 가이드 → 대화/질문 → 실천 놀이 → 참고자료·안전·연령별 변형**이다. 도입·대화·마무리는 해당 맥락 안에서 이어지게 한다. 모든 책에 같은 섹션 수·활동 수를 요구하지 않는다. 사용자가 다른 순서를 정하면 우선하고 사유를 기록한다. 비슷한 활동은 같은 목표 아래 기본/확장 활동으로 통합 제안할 수 있지만 고유 설명·도구·예시·교육적 의도는 보존한다. 통합 전후 이동·삭제·의미 변화와 승인 범위를 별도로 보고한다.

`thinking.activities`와 각 `steps`의 배열 순서가 표시 순서의 기준이다. ID는 제목·순서 변경 시 유지한다. 선택적으로 활동/단계의 `extensions.presentation`에 다음을 둔다.

- `type`: `guide`, `conversation`, `discussion`, `experiment`, `creative`, `practice`, `reference` 등 **열린 문자열**. 새로운 유형도 허용하며 필수 enum이 아니다.
- `section`: 논리적 그룹 ID. 예: `dialogue-guide`, `daily-play`.
- `order`: 선택적 양의 정수. 같은 배열 안에서 중복되거나 배열 순서와 충돌하면 오류로 보고하며 조용히 정렬하지 않는다. 생략해도 유효하다. 순서 변경은 사용자가 승인한 후보로만 한다.
- `numberingGroup`: 대화/실천의 번호 계열을 분리하는 ID. 예: `dialogue`, `practice`.
- `numbering`: `auto` 또는 `none` 선택. 가이드·참고자료는 번호를 생략할 수 있다. 최종 번호는 저장하지 않고 후속 변환기가 그룹별로 한 번 생성한다.
- `originalHeading`, `sourceRanges`: 원래 번호·제목과 문서/문단 위치 보존용 메모. 원문 추적 기록이지 변경 권한이 아니다.

활동은 title/description, 단계는 title/goal/questions/explanation을 우선 사용한다. 준비물·발화자별 대화·확장 활동·마무리는 각각 활동/단계의 `extensions.materials`, `turns: [{speaker, text}]`, `variants`, `closing` 등에 선택 보존할 수 있다. `speaker`는 부모/아이/상황 등 원문 역할을 유지하며 대화를 설명과 합치지 않는다. 새 필수 필드가 아니다. `thinking.extensions.presentation.orderPolicy: "user"`와 `reason`은 사용자가 정한 순서를 설명하는 선택 메모이며 승인 증거가 아니다.

제목에는 화면용 번호를 중복 저장하지 않는다. 가져온 번호는 originalHeading과 원문 사본에 남기고 번호 없는 제목 후보를 제안한다. `#### 1)` 제목, HTML 순서 목록, UI/CSS 번호가 중복되는지 후속 변환/Preview에서 확인한다. 현재 Astro 호환 문자열을 description 안에 작성하도록 강제하지 않는다. 구체적인 직렬화 계약은 [handoff.md](handoff.md)에 있다.
