# 부분 수정과 호환 경로

모드별 작성법은 SKILL.md의 각 가이드를 따른다. 공통 규칙은 common-guide.md에만 둔다.

revise는 선택된 콘텐츠만 후보에서 바꾼다. 예: 장면 ID로 text만, 활동/단계 ID로 질문만, 에세이 결론 구역만, 이미지 sceneId로 prompt만. 대상이 모호하거나 같은 문장이 여러 곳에 있으면 먼저 확인한다.

- 인덱스로 요청받으면 현재 파일을 읽어 고유 ID를 함께 기록한다.
- 해당 ID의 현재 JSON Pointer를 구하고 변경 전후를 검사한다. 예: `/story/scenes/1/text`. 이 포인터는 이번 후보 검사용이며 영구 ID가 아니다.
- 전역 연령 변경은 metadata 또는 기획의 연령 필드만 수정하고 동화·에세이를 함께 재생성하지 않는다. 다른 원고의 연령 적합성 재검토 필요를 보고한다.
- 범위가 에세이 본문 일부라면 JSON Pointer 검사는 body 전체 허용이므로 선택 문장/구역 밖 텍스트는 별도 diff로 확인한다.
- 검사에 실패하면 허용 범위를 넓혀 통과시키지 않는다. 범위 밖 변경을 되돌리거나 사용자의 별도 요청을 기다린다.
- 승인 전 정본 반영 금지, 승인 후에도 선택 범위만 반영한다.

[후보 검사 명령](validation.md)과 [사용 예시](../examples/sample-workflow.md)를 참고한다.

## 분류·통합 수정의 전달

Essay/Play 재분류, 표시 순서 변경, 번호 추출, 유사 활동 통합도 revise의 선택 변경이다. 원문 문단/ID→후보 필드 대응, 고유 설명·예시·도구의 보존, 삭제한 문구(없으면 없음), 실제 승인 범위를 보고한다. 기존 Master Draft와 출판 JSON이 다르다는 이유로 정본을 덮어쓰지 않는다. handoff는 원고 수정 권한이 아니며 승인된 입력의 사본과 미해결 검토만 전달한다.
