# 디자인 진단과 비교 시안

## 판단

소규모 가족 파일럿에는 **A안**을 권장한다. 현재 탐색 방식을 보존해 사용자가 책을 찾는 데 드는 변화가 작고, 카드·타이포·필터 정돈만으로 구현 범위를 제한할 수 있다. **B안**은 표지 옆에 핵심 질문이 이어져 부모가 질문을 기준으로 책을 고르는 데 더 적합하다. 다만 5권을 훑는 스크롤이 길고 모바일에서는 A와 모두 세로 카드가 되어 차이가 줄어든다. B의 편집형 방향은 파일럿에서 질문 중심 선택이 유효한지 확인한 뒤 채택할 수 있다.

실제 비교에는 몽·루미·림보·비밀의 망토·피코 5권의 동일한 제목·표지·핵심 질문·소개·추천 연령·분류를 사용했다. 질문/문구를 생성하거나 출판 JSON을 수정하지 않았다. 표지의 `contain` 처리는 원본 전체를 보여주며, 비율이 다른 표지에 종이색 여백이 생긴다. 이를 이미지 누락으로 오해하지 않도록 추후 표지 규격 결정 필요.

## 검증과 한계

- 브라우저: 로컬 Chromium + Playwright. 360/390/768/1440px 각각 A/B 5권, 긴 실제 제목·질문, 빈 검색, 초기화(5권 복원), 분류 선택 aria-pressed, 연령 복합 조건 확인. 홈·대표 에세이·활동 가로 넘침 없음. 이미지 decode 후 캡처. `browser-results.json`.
- 대표 읽기 A/B 390px: 1→2→1쪽 이동, 부모 힌트 expanded, 마지막 쪽→읽기 완료→생각 나누기 인라인 가이드, 화살표 키 탭 선택 확인. `function-results.json`. 단일 질문은 별도 질문 화면이 아닌 인라인 펼침이 정상 동작이다.
- 질문 0/1/다중 처리는 기존 단위 테스트로 검증. 모든 실제 책·모든 질문을 브라우저에서 완독한 것은 아니다. 스크린리더·실물 iOS/Android·200% 확대·모든 색 조합의 수동 대비 검사는 미실시.
- `npm test`: 124개 중 123 통과, 1 skip, 실패 0. `npm run content:check` 통과. 원본 해시/등록 관련 기존 테스트 포함. 과거 결과를 인용하지 않고 이번 세션에서 재실행.
- `npm run check`: 최종 별도 로그 참조. Hallmark fixture가 프로젝트 검사에 혼입된 임시 3개 오류는 도구 격리/fixture 제외로 해결. 체크 결과를 선택적으로 성공 처리하지 않음.

- 최종 시각 검토는 동일 에이전트가 스크린샷을 다시 읽는 방식이며 독립 심사자 검토를 했다고 주장하지 않는다.
- 실서비스 URL의 배포본은 직접 검증하지 않음. 최신 main 소스의 로컬 빌드가 진단 기준이다.

## 실제 반영 계획 — 이번에는 실행하지 않음

1. 선택한 안의 색/간격/글꼴을 `src/styles/global.css` 테마 토큰으로 통합. 포커스 대비와 disabled/hover/active 상태를 재점검.
2. `src/pages/index.astro`: A는 여백·타입, B는 소개 2열/반응형. 원문 변경 없이 시작.
3. `src/components/library/BookCard.astro`: 표지 contain·제목/질문 크기·소개 비절단·태그/외곽 정돈. 운영 링크와 data-book 계약 유지.
4. `src/components/library/LibraryShelf.astro`: 필터 스타일/그리드만 변경. matchesBook·reset·aria-live·noscript 보존.
5. `src/styles/book.css`, `src/styles/reading.css`, 필요 시 `src/styles/story-viewer.css`: 범위를 한정해 읽기 테마 정리. StoryViewer/ReadingCompletion 로직은 변경 대상 아님.
6. 같은 check/test/content:check/build + 접근성/포커스/실물 모바일 회귀 확인. 별도 검토 이후에만 반영/병합/배포 논의.

시안용 `design-preview/src/components/`는 원본 서가 컴포넌트의 검토용 사본이다. 변경은 격리 링크 prop 추가와 import 경로뿐이며 실제 반영에서는 사본을 유지하지 않고 운영 컴포넌트로 스타일을 옮긴다. 등록기/콘텐츠 스키마/원고/이미지/승인 기록/원본 해시/배포 설정은 디자인 적용 대상이 아니다.

## 이미지 경량화 후속 계획

실제 출판 참조 60개, 총 185,125,756바이트(약 176.5MiB). 디스크 public/images 약 177M. 현재 문자열 `/images/...`를 그대로 제공하는 public 자산이며 카드에 srcset/sizes 없음. Astro 자동 최적화 경로를 사용하지 않는다. 표지 5개 합계 약 15.50MB: 몽 174,909B, 루미 3,068,637B, 림보 174,186B, EP05 8,726,743B, 피코 3,353,194B. 가장 큰 장면은 EP05 page12 9,177,089B. 전체 경로·크기·해상도·형식은 `images.json`.

후속 작업은 별도 성능 변경으로 진행:

- 원본 이미지·제작 원고·기존 경로를 보존. 원본 해시를 key로 파생 manifest를 생성하고 이미 있는 원본을 재인코딩/덮어쓰기/삭제하지 않는다.
- 표지 파생 폭 320/480/640/960px, 본문 640/960/1440/1920px(원본보다 확대하지 않음). WebP와 AVIF 후보를 별도 디렉터리에 생성하고 삽화·글자·색 경계 품질 검수 후 채택. 용량 목표는 검증 전 추정치이며 절감률을 보장하지 않는다.
- `<picture>` AVIF/WebP source + 기존 원본 img fallback, srcset/sizes 적용. A 3열/B 2영역/모바일 실폭을 sizes에 연결. 실제 width/height로 CLS 예약.
- 첫 화면 표지 1장만 eager/fetchpriority high 검토, 나머지 lazy. 뷰어 현재 장면 우선, 다음 장면 제한 prefetch. 전체 장면 선다운로드를 기본으로 하지 않는다.
- `src/lib/image-variants.ts` 같은 표시 계층에서 원본 경로→manifest 조회. 파생이 없으면 기존 경로 반환해 호환 보존. JSON의 cover/pages.image와 출판 원고는 그대로 유지.
- `scripts/book-import.ts`의 등록 완료 단계에 선택적인 파생 생성 명령 연결. 먼저 원본/소유권/승인/해시 검증, 이후 별도 파생 manifest 생성. 실패해도 원본은 보존하고 파생 실패를 명시. 기존 등록 미리보기는 읽기 전용 유지.
- 대표 5표지·큰 EP05 장면을 골라 별도 샘플로 품질/전송 바이트/LCP/CLS 비교 후 전체 적용 여부 결정. 이번 단계에서 파생 생성 또는 성능 개선을 수행하지 않았다.

## 선택과 확인 사항

A 또는 B를 선택하면 다음 단계의 변경안을 구체화할 수 있다. 추천은 A. 확인할 사항은 B의 명조 제목 선호, 전체 표지 보존 시 여백 허용, 모바일 소개 축약 여부, 한글 폰트 자체 호스팅 여부다. 어떤 항목도 승인 전 운영 원문에 임의 반영하지 않는다.

별도 문구 제안(미반영): 조건 초기화 버튼의 ‘전체 책 보기’를 ‘조건 초기화’로 구분하면 분류 전체 버튼과 역할이 명확해진다. 소개 문장 축약은 원문/대체문을 따로 비교한 후 결정한다.

## A안 선택 후 수정

사용자는 A안을 선택하고 EP01 첫 장면을 사용하는 표지의 여백 제거를 요청했다. A안 EP01 서가 표지는 `object-fit: cover`와 중앙 정렬로 4:3 영역을 가득 채우도록 수정했다. 원본의 1024×572 비율을 유지하므로 좌우가 일부 잘리며 그림을 늘려 왜곡하지 않는다. 나머지 표지와 본문 뷰어의 표시 방식은 유지한다. 앞선 전체 표지 contain 권고보다 이 사용자 선택을 우선한다. 운영 소스/원본 바이트는 변경하지 않는다.
